# CLULatent security policy (Phase 1.6)

## Threat model

A `.clulatent` package is a plain directory of JSON/JSONL/media/SQLite
files. Once ingested, it is expected to be copied, shared, downloaded,
and re-opened by tooling that did not create it. From that point on,
every file inside the package must be treated as **untrusted input**:

- `manifest.json` and every `tracks/*.jsonl` record may be hand-edited
  or generated by a malicious or buggy tool.
- `index/search.sqlite` is derived and disposable, but is still
  untrusted on the *read* path — it can be missing, corrupt, or
  maliciously crafted.
- Every package-relative path string embedded in the manifest or a
  track record (`source.stored_path`, `tracks[].file`,
  `media.keyframes.dir`, `index.file`, `receipts.file`,
  per-record `payload.path`) is attacker-controlled.
- The source media file passed to `ffmpeg`/`ffprobe` is untrusted;
  either tool may hang, crash, or emit unbounded output on malformed
  input.

CLULatent is a local-first CLI, not a server: the threat model is a
single user running `clulatent inspect/timeline/query/validate/reindex`
against a package they downloaded or received from someone else, not a
multi-tenant service parsing packages from arbitrary strangers at
scale. The goal of Phase 1.6 is that none of the read-only commands can
be tricked by a malicious package into escaping the package directory,
exhausting memory/CPU, hanging indefinitely, or altering the user's
terminal.

## What is explicitly out of scope (Phase 1)

- **Sandboxing / containers.** Commands still run with the invoking
  user's OS permissions. Path containment prevents *filesystem*
  escapes from package data, but this is not a substitute for an OS
  sandbox.
- **Package signing / provenance.** There is no cryptographic
  signature on a `.clulatent` package; `validate` checks internal
  consistency, not authenticity.
- **`clulatent ingest`'s own inputs.** The *video file you choose to
  ingest* is assumed to be one you trust enough to hand to `ffmpeg`
  locally, same as running `ffmpeg` directly. Ingest is still hardened
  against resource exhaustion (size/duration caps, subprocess
  timeouts) since even a trusted-source video can be huge or
  malformed, but it is not treated as adversarial in the same sense as
  a downloaded `.clulatent` package.

## Defenses, by module (`src/clu_latent/security/`)

| Module | Defends against |
|---|---|
| `paths.py` | Path traversal / symlink escape via any manifest- or track-declared path string. Two-stage: lexical rejection (`validate_relative_posix`) before any filesystem call, then containment + symlink-leaf rejection (`resolve_in_package`) after resolving real paths. |
| `jsonl.py` | Memory exhaustion from an oversized `manifest.json` or `tracks/*.jsonl` (bounded whole-file read / streamed per-line read with a line-size cap and a record-count cap). |
| `subprocess.py` | A hung or output-spamming `ffmpeg`/`ffprobe` process (hard timeout with process-group kill, bounded stdout/stderr capture, `stdin=DEVNULL`, never `shell=True`). |
| `sqlite.py` | A missing, corrupt, or symlinked `index/search.sqlite` (always opened read-only via a safe URI, with a sanity probe before use). |
| `temp.py` | A partially-written package being left at the final output path on ingest failure (build-in-temp-dir, atomic rename on success only). |
| `console.py` | Terminal/Rich-markup injection from package-derived strings rendered via `console.print` (ANSI/control-character stripping + Rich markup escaping). |
| `limits.py` | Single source of truth for every numeric threshold used above, so limits are auditable in one place. |
| `operation_lock.py` | Two `clulatent` write operations (`ingest`, `lock`, `reindex`) corrupting the same package by racing each other; not a security boundary, see "Package locking" below. |

## Reader responsibilities by command

- `inspect`, `timeline`, `query`: read-only; every manifest/track path
  is resolved via `security.paths.resolve_in_package`, every printed
  string derived from package data goes through
  `security.console.safe_console_text`.
- `validate`: the **strict** reader — any malformed JSONL line,
  schema mismatch, or path/containment violation is a hard error.
  Never modifies the package.
- `reindex`: the **tolerant** reader for track *content* (a malformed
  individual JSONL line is skipped with a warning) but still enforces
  every hard resource limit (line size, record count) and path
  containment check as a failure, never a warning. Only ever writes
  the derived `index/search.sqlite`.
- `ingest`: builds into a `security.temp.staged_package_dir` temp
  directory (always a sibling of the requested output path, so the
  final commit is a same-filesystem atomic `rename`) and only commits
  via `security.temp.commit_package` once every step succeeds. Enforces
  `max_source_file_bytes` before copying and `max_media_duration_ms`
  after probing. A failed run still writes a
  `<output>.failure-receipt.jsonl` audit trail next to the (never
  created, or discarded) output path, since the temp package itself is
  always removed on failure.

## Default limits (`security/limits.py`)

| Limit | Default | Rationale |
|---|---|---|
| `max_source_file_bytes` | 2 GiB | Caps ingest input size. |
| `max_media_duration_ms` | 2 hours | Caps ffmpeg/ffprobe wall-clock work per ingest. |
| `max_manifest_bytes` | 1 MiB | `manifest.json` is a single small JSON document. |
| `max_jsonl_line_bytes` | 1 MiB | Caps a single JSONL record. |
| `max_records_per_track` | 1,000,000 | Caps total records read from one track file. |
| `ffprobe_timeout_s` | 30s | Metadata probing should be near-instant. |
| `ffmpeg_timeout_s` | 900s | Keyframe extraction on long/large sources. |
| `stderr_tail_bytes` | 64 KiB | Bounded stderr kept in receipts/errors. |
| `max_stdout_capture_bytes` | 16 MiB | ffprobe JSON output cap (assumption, tunable). |
| `max_stderr_capture_bytes` | 8 MiB | ffmpeg/ffprobe stderr spam cap (assumption, tunable). |

All limits are a single `Limits` dataclass (`DEFAULT_LIMITS`), threaded
explicitly through every entry point (`ingest_video`, `validate_package`,
`reindex_package`, `Manifest.from_json_file`, `read_track_file`) rather
than read from global state, so a caller can override them per call
(e.g. in tests) without any hidden coupling.

## Receipts

`receipts/ingest.jsonl` records one entry per ingest operation,
including (where applicable) the resolved absolute path of the
`ffmpeg`/`ffprobe` binary actually invoked, whether that invocation was
killed for exceeding its timeout or output cap, a bounded stderr tail,
and — on the final `ingest_summary` entry — a full snapshot of the
`Limits` in force for that run. This makes a receipt self-contained
evidence of *what ran, with what bounds, and what happened* even after
the fact.

## Optional ML dependencies (Phase 1.7B/1.7C)

`clulatent ingest` always runs ffmpeg's `silencedetect` filter (Phase
1.7A: `silence`/`non_silent_audio` events) — this is non-ML, plain
signal-level analysis, so it has no opt-in flag and no extra
dependency.

Silero VAD (`--vad`, `speech_activity` events) and faster-whisper
(`--transcribe`, `speech_segment` events) are different in kind: both
are optional ML dependencies (`pip install clu-latent[vad]` /
`clu-latent[whisper]`), and both are strictly **opt-in at runtime**:

- `torch`/`silero_vad`/`faster_whisper` are imported **lazily**, never
  at module import time. Importing `clu_latent.cli` (or `ingest.py`,
  which no longer imports `vad.py`/`transcribe.py` at module top) does
  not import any of them; a plain `clulatent inspect`/`validate`/
  `ingest` therefore never loads torch/silero-vad/faster-whisper. The
  heavy imports happen only inside `vad.detect_speech_activity()` /
  `transcribe.transcribe_audio()`, which are only reached when the user
  passes `--vad`/`--transcribe`. `vad.py`/`transcribe.py` keep the
  engine symbols bound to `None` until first real use and raise a clean
  `VadUnavailableError`/`WhisperUnavailableError` (never a raw
  `ImportError`) if the extra is not installed. Even
  `vad.is_available()`/`transcribe.is_available()` use
  `importlib.util.find_spec`, so merely probing for the engine never
  imports it. This is covered by import-guard tests
  (`tests/test_lazy_ml_imports.py`) that run a fresh interpreter with a
  `sys.meta_path` tracker and assert none of the three packages is even
  looked up during CLI import or a plain ingest.
- No model weights are ever loaded, and no network request is ever
  made, as a side effect of a plain `clulatent ingest`. A download can
  only happen as a direct, traceable consequence of the user passing
  `--vad` or `--transcribe` (and, for faster-whisper, only when
  `--whisper-model-path` — a local model directory — is *not*
  supplied; passing it avoids any network access).
- No cloud APIs are called by either integration; transcription and
  VAD inference always run locally.
- `--vad`/`--transcribe` without the corresponding extra installed
  raises a clean `IngestError` (via `VadUnavailableError`/
  `WhisperUnavailableError`) naming the missing extra — never a raw
  `ImportError` or a partially-written package.
- Audio extracted for VAD/transcription input (`extract_audio_wav`) is
  written to a `tempfile.TemporaryDirectory()` **outside** the staged
  package directory, never under it — `security.temp.commit_package`
  does a blanket rename of the whole staged directory, so anything
  placed inside it would ship inside the final `.clulatent` package.

Phase 1.8 (pyannote.audio speaker diarization) is explicitly out of
scope and not implemented.

### Duration-bound events (Phase 1.7.1)

A model's own decode/timestamp output is untrusted the same way any
other producer-generated data is: faster-whisper can (and, in
practice, sometimes does) return a `speech_segment` ending well past
the ffprobe-reported duration of the source media. No event in any
canonical track is allowed to exceed the source's known
`duration_ms`, except for a small tolerance
(`EVENT_DURATION_TOLERANCE_MS`, `constants.py`, default 1000ms) that
exists solely to absorb legitimate codec/stream-metadata rounding
between what ffprobe reports and what a decoder or model considers
"duration" — not to silently accept a genuinely broken timestamp.

This is enforced on both sides of the boundary:

- **`ingest`**: before a faster-whisper segment becomes a canonical
  `speech_segment` event, `transcribe.clamp_segments_to_duration()`
  compares it against `duration_ms + tolerance_ms`. A segment starting
  beyond that limit is dropped entirely; a segment only ending beyond
  it is clamped down to `duration_ms`; if clamping would leave
  `t_end_ms <= t_start_ms`, the segment is dropped instead of kept as
  a zero/negative-length span. Every clamp or skip is recorded as a
  non-fatal `warnings` entry on the `transcribe_audio` receipt in
  `receipts/ingest.jsonl` — the ingest still succeeds, but the
  normalization is auditable after the fact.
- **`validate`**: the strict reader independently re-checks every
  event in every canonical track (not just freshly-transcribed ones)
  against the same `duration_ms + tolerance_ms` bound, and fails the
  package if any `t_start_ms` or `t_end_ms` exceeds it — this catches
  hand-edited packages, packages produced before this normalization
  existed, or any other producer that skips the ingest-time clamp.
  Negative timestamps and `t_end_ms < t_start_ms` are already hard
  failures independent of this check, enforced by `EventEnvelope`'s
  own Pydantic validators the moment a record is parsed.

## Package locking (Phase 1.7.5)

`clulatent lock`/`verify-lock`/`lock-status` add a **local hash
manifest** (`lock/package.lock.json` + `lock/package.lock.sha256`) that
lets a later `verify-lock` detect whether a package's canonical files
changed since locking. This is tamper-*evidence*, not a security
boundary and not a cryptographic identity signature — it does not stop
anyone with filesystem access from editing or deleting any file in the
package, including the lock files themselves. See `docs/LOCKING.md` for
the full explanation of what locking does and does not prove, and why
it is deliberately not encryption, DRM, or cloud/authority-backed
signing.

`lock/package.lock.json` is written the same way every other
package-derived write in this codebase is: hashed via `hash.sha256_file`
(constant-memory streaming, same as `sources/source.sha256`), read back
via bounded readers (`security.jsonl.read_bytes_bounded`), and every
path it reads or writes is resolved with the same symlink-refusal rule
as `security.paths.resolve_in_package` (the `lock/` directory itself is
refused if it is, or is reached through, a symlink — see
`lock._ensure_safe_lock_dir`/`security.operation_lock._ensure_safe_lock_dir`).

Separately, `security/operation_lock.py` provides a short-lived,
cooperative write guard held for the duration of a single write
operation (`ingest`, `lock`, `reindex`) to prevent two concurrent
`clulatent` invocations from corrupting the same package. For `lock`
and `reindex` this lives at `lock/package.operation.lock.json` inside
the existing package (`operation_lock`); `ingest` targets a package
that doesn't exist yet for most of its run (see "Atomic ingest"
above), so it uses a sibling file next to the requested output path
instead — `<output_path>.oplock.json` (`ingest_target_lock`) — sharing
the same acquire/stale/release core (`_guarded_lock`). Neither is a
security boundary — both are local pid/hostname bookkeeping, not an
access-control mechanism, and a `--force-stale-lock` override exists
on all three commands specifically for clearing a lock left behind by
a crashed process (only when the recorded pid is confirmed gone or the
lock's age exceeds a safe threshold).

## Notable behavior decisions

- **Blank lines in JSONL are always skipped silently**, never yielded
  as a record and never flagged as a warning/error — this matches how
  track files have always been written (`write_track_file` never emits
  blank lines) and keeps `iter_jsonl_bounded` the single shared reader
  for both the strict (`validate`) and tolerant (`reindex`) paths.
- **Backslashes in a package-relative path are rejected, not
  silently converted** to forward slashes. Earlier (pre-1.6) code
  normalized `media\keyframes\x.jpg` into a clean POSIX path; that
  normalization step is itself removed as a latent security gap — a
  package's on-disk path string must already be clean POSIX form, or
  it is refused outright.
